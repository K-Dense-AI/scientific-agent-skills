# RMBase capability audit

Audit date: 2026-09-23. Base: `http://bioinformaticsscience.cn/rmbase/`.
Evidence: public HTML, linked first-party JavaScript, ordinary form POST requests,
saved JSON/HTML responses, and one official 6,369,162-byte human gene archive.
Requests were sequential and spaced approximately two seconds apart. No browser
automation, privileged access, server modifications, or endpoint enumeration was
used. Runtime network calls were reproduced from source; a browser Network panel
was not used. HTTPS certificate validation failed with an expired-certificate
error. HTTP worked. Site-root robots.txt returned 404, which is not a grant of
bulk-crawling permission.

## Query capabilities

All endpoint paths below are relative to the base. AJAX calls use POST with
`application/x-www-form-urlencoded` and return JSON arrays (sometimes with embedded
HTML). `assembly` is the genome build, while `genome` is the species name.
Exact offered combinations are in [catalog.json](catalog.json), transcribed from
the linked menu objects without evaluating JavaScript. Catalogue presence is
not proof every species/endpoint combination was live-tested.

Source scripts are `js/ajaxJS/{modGeneAjax,m6AmodSiteAjax,modmodSiteAjax,
modEnzymeAjax,modsnoRNAAjax,modClusterAjax,modRBPAjax,modMirTarAjax,modVarAjax,
modHistoneAjax.new,modMotifAjax,modOtherMotifAjax}.js`; RMP AJAX is inline in its
returned detail page. These are public website requests, not a versioned API.

Modification detail `db` and `table` values are narrowly constructed from the
published links, never arbitrary database inputs. Human RNA-editing uses
`hg38_rnaeditingbase_modsite_all`; m6A uses `<assembly>_m6abase_modsite` in the
currently active script. Missing-ID HTML echoes the requested ID but has `mod Site`
equal to `:-:` and empty type/sequence; this observed placeholder is parsed as no
records. An unfamiliar broken page raises an error.

No query authentication/cookies were needed in the live tests. The forms mostly
have no action because JavaScript sends AJAX requests. JavaScript is needed for
the interactive website's menus/rendering, not for the reproduced data requests.
The DataTables setup consumes the full array, then paginates/searches locally.
Excel exports are browser-side DataTables buttons, not separate evidence of an
Excel download API. The client exports JSON/TSV itself.

## Additional discovered functions not exposed as complete CLI workflows

- `snornaguidepseudo.php` has POST forms `snoBrowseRes.php` (`category[]`) and
  `snoCDBrowseRes.php` (`categoryCD[]`); single-item links use
  `snoBrowsePlus.php?snoID=...` / `snoCDBrowsePlus.php?snoID=...`. An ordinary GET of
  the published SCARNA11 link succeeded; it references `ajaxFiles/getSnoRNABrowse.php`.
  Visual snoRNA alignment browsing is not implemented in this release.
- RMP forms POST to `rbpDiffDetail.php` (`rbpType`, `rbpsource`, `rbpDataType`),
  `cancerDetail.php` (`tumor`, `source`, `datatype`) and `corDetail.php`
  (`cortumorType`, `genename`). Each returned HTML in smoke tests. Discovered
  additional JSON requests: `getCancerResRBP.php` (`rbp`, `datatype`, `btnID`),
  `getCancerRes.php` (`tumorType`, `tableName`), `getCancerResCorTable.php`
  (`gene1`, `tumor`), `getCancerResCor.php` (`tumor`, `gene1`, `gene2`). Their plotting
  and correlation workflows are not implemented. The CLI exposes the verified RMP
  table sections only and does not assign hg38 to undeclared TCGA coordinates.
- `rnamodifications.php` is a static summary table and has an HTML-to-Excel form
  `phpfiles/dlExcel.php` with `excelContent`; no need to call it for scientific data.
- Enzyme, cluster, snoRNA, RBP and miRNA results include further detail links.
  Their existence is documented, but this release does not parse every drilldown.

No capability was demonstrated to require browser automation. This does not mean
all interactive visualizations have been reproduced.

## Uploads and task IDs

| Page | Form action (host-root path) | Fields | Observed status |
| --- | --- | --- | --- |
| `toolsmodannotation.php` | `/cgi-bin/runModAnno.pl` | `group`, `genome`, `Species`, `bedTextArea`, file `bedInputFile` | REMOTE_ANALYSIS; one public example BED6 upload returned 503 |
| `toolsmodmetagene.php` | `/cgi-bin/runModMeta.pl` | same | REMOTE_ANALYSIS; one small example submission returned 503 |
| `toolsmodGeneTool.php` | `/cgi-bin/runModgenetool.pl` | same plus `tooltype=modgene`, `rbp=Gene Case|Transcript Case` | REMOTE_ANALYSIS; one public Ensembl ID submission returned 503 |

All three forms use multipart/form-data POST. Annotation/metagene pages require
BED6 smaller than 2 MB and unique fourth-column names. GeneTool takes gene or
transcript ID lists, not BED. Its upload form clears text to `Input ID List`.
The gene-tool CLI currently submits Gene Case only.

Annotation and GeneTool expose `toolsresult.php` multipart POST with
`tooltyperes=MODANNO|MODGENE` and `resultID`; pages say IDs remain queryable for one
week. No successful task ID, status response, polling contract, or result download
was obtained. They are **unverified**, not functioning async APIs. The client never
invents task-ID regexes, enumerates IDs, or polls guessed paths. `task` returns exit
7 without networking. A future successful submission requires validating the
actual response before implementing submit/status/result completion.

## Upstream fit and coverage conclusion

Reviewed upstream commit `49c6e97775eaa18ba791bebe23162a70ae601c18`:
AGENTS.md, CONTRIBUTING.md, database-lookup, BioServices, gget, DepMap, script/test
layout, tests/skill-requirements.toml and CI workflows. No existing RMBase adapter
was found. The standalone **rmbase** skill is recommended: it owns website-specific
request contracts, HTML parsers, datasets, assembly semantics and analysis failure
behavior. BioServices/gget coverage does not replace these RMBase workflows.
`database-lookup` emphasizes documented APIs; duplicating this adapter there would
create competing canonical contracts. A short discovery cross-reference may be
considered separately if maintainers request it.

The core METTL3 research lookup is feasible with no server changes and no manual
web interaction. Much of the eight-module site's tabular surface is HTTP-callable;
coverage is explicitly per row above, not an unsupported percentage. Full visual
browsing, all detail pages, all download formats and successful remote analyses
remain outside verified coverage. A scoped lookup/cache PR can be proposed after
validation; claiming complete RMBase tool coverage would be premature.

FUTURE_RECOMMENDATION: optional official versioned endpoints, declared coordinate
schemas, checksummed datasets and documented task status would improve stability.
They are not dependencies for the working query/cache adapter.
